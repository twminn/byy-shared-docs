# Incident Report: Stripe Webhook Delivery Failure

**Date:** May 5, 2026
**Severity:** High
**Owner:** Engineering (Trent Minneman)
**Audience:** Analytics Team, Engineering Team, DevOps

---

## Summary

Stripe webhook delivery to `https://bestyearyet.io/stripe/webhooks` has been failing since approximately **May 1, 2026**. The root cause was the pricing experiment CloudFront proxy (distribution `E1TYH0C1AQM1MP`) stripping the `Stripe-Signature` HTTP header before requests reached the Rails origin. This header is required for webhook signature verification.

**Duration:** ~May 1 – May 5, 2026 (approximately 4–5 days)

---

## Root Cause

When the experiment proxy was deployed for `bestyearyet.io` on May 1 (see [Deployment Notice](./05.01.26-EXPERIMENT_PROXY_DEPLOYMENT_NOTICE.md)), all traffic to the domain began routing through CloudFront distribution `E1TYH0C1AQM1MP`.

The origin request policy (`byy-experiment-origin-request-rails`) only whitelists **4 headers** to forward to the origin:

| Header | Purpose |
|--------|---------|
| `X-BYY-VID` | Experiment visitor ID |
| `X-BYY-Variant` | Experiment variant assignment |
| `Host` | ALB SSL certificate matching |
| `X-BYY-VID-New` | New visitor flag |

All other request headers — including **`Stripe-Signature`**, `Content-Type`, and `User-Agent` — were stripped by CloudFront before reaching the Rails application.

### Failure chain

```
1. Stripe sends POST to https://bestyearyet.io/stripe/webhooks
   └─ Includes Stripe-Signature header for payload verification

2. DNS resolves to CloudFront proxy (E1TYH0C1AQM1MP)
   └─ Lambda@Edge viewer-request runs (assigns visitor ID — no error)

3. CloudFront forwards request to ELB origin
   └─ Origin request policy STRIPS Stripe-Signature header

4. Rails receives POST without Stripe-Signature
   └─ Stripe::Webhook.construct_event(payload, nil, secret) → SignatureVerificationError
   └─ Controller returns 400

5. Stripe marks webhook as failed and enters retry loop
   └─ All retries fail for the same reason
```

### Timeline

| Date | Event |
|------|-------|
| Apr 28, 17:32 UTC | Last successful webhook delivery (`customer.subscription.updated`) |
| May 1 | Experiment proxy deployed for `bestyearyet.io`; DNS changed from `A → ELB` to `A alias → E1TYH0C1AQM1MP` |
| May 1 – May 5 | All Stripe webhooks fail (Stripe-Signature header stripped by CloudFront) |
| May 5 | Issue identified and fix deployed |

---

## Fix Applied

A dedicated CloudFront **cache behavior** was added for path `/stripe/webhooks` on distribution `E1TYH0C1AQM1MP`:

| Property | Value |
|----------|-------|
| Path pattern | `/stripe/webhooks` |
| Lambda@Edge | **None** (bypasses experiment pipeline entirely) |
| Cache policy | `Managed-CachingDisabled` (`4135ea2d-6df8-44a3-9df3-4b5a84be39ad`) |
| Origin request policy | `Managed-AllViewer` (`216adef6-5c7f-47e4-b989-5492eafa07d3`) — forwards ALL viewer headers |
| Allowed methods | GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS |

This is the same pattern used for the `/cable` behavior (WebSocket bypass).

### Why this fix is correct

1. **Bypasses Lambda@Edge** — Stripe webhook POSTs are server-to-server calls that don't need experiment variant assignment. Running them through the experiment pipeline is unnecessary overhead.
2. **Forwards all headers** — The `Managed-AllViewer` policy forwards every header the viewer sends, including `Stripe-Signature`, `Content-Type`, and `User-Agent`, all required by the Rails webhook controller.
3. **No caching** — `Managed-CachingDisabled` ensures POST requests are never cached.

## Impact Assessment

### What was affected

- **Subscription renewals:** The Rails app did not receive `invoice.payment_succeeded` or `customer.subscription.updated` events. Users' subscription status may not have been refreshed in the local database. **Note: Stripe still collected payments normally** — only the notification to our app was lost.
- **New signups via checkout:** `checkout.session.completed` events were not processed. New users who signed up during this window may not have had their accounts properly activated (subscription status, GHL sync, affiliate attribution, GA4 tracking).
- **Cancellations:** `customer.subscription.deleted` events were not processed. Any cancellations during this window may not be reflected in the app.

### What was NOT affected

- Stripe payment processing (charges, invoices, refunds all continued normally)
- Direct user authentication and app functionality
- WebSocket/ActionCable (`/cable` has its own bypass behavior)
- Static marketing sites (separate CloudFront distributions)

---

## Remediation Steps

1. **CloudFront fix deployed** (May 5) — `/stripe/webhooks` cache behavior added
2. **Diagnostic endpoint added** — `POST /stripe/webhooks/health` returns header forwarding status for verification
3. **Stripe event replay** — Failed events from May 1–5 will be replayed via Stripe dashboard or API to reconcile any stale subscription states

---

## Recommendations for Future Proxy Changes

When adding new paths or services behind the experiment proxy, consider whether they require specific headers that aren't in the experiment origin request policy whitelist. Server-to-server endpoints (webhooks, API callbacks, health checks) should have dedicated cache behaviors that:

1. **Bypass Lambda@Edge** (no experiment assignment needed)
2. **Forward all viewer headers** (use `Managed-AllViewer` origin request policy)
3. **Disable caching** (use `Managed-CachingDisabled` cache policy)

### Paths that should always bypass the experiment proxy

| Path | Reason |
|------|--------|
| `/cable` | WebSocket upgrade headers required (already bypassed) |
| `/stripe/webhooks` | Stripe-Signature header required (now bypassed) |
| `/health` or `/up` | Health check endpoints (consider adding) |

## Terraform Sync Notice

This fix was applied via AWS CLI directly to distribution `E1TYH0C1AQM1MP`. The Terraform configuration in `byy-marketing-analytics` should be updated to include the `/stripe/webhooks` cache behavior to prevent drift on the next `terraform apply`.

```hcl
# Add to the bestyearyet.io proxy distribution's ordered_cache_behavior blocks:

ordered_cache_behavior {
  path_pattern     = "/stripe/webhooks"
  target_origin_id = "rails-app"

  allowed_methods = ["GET", "HEAD", "OPTIONS", "PUT", "PATCH", "POST", "DELETE"]
  cached_methods  = ["GET", "HEAD"]

  cache_policy_id          = "4135ea2d-6df8-44a3-9df3-4b5a84be39ad"  # Managed-CachingDisabled
  origin_request_policy_id = "216adef6-5c7f-47e4-b989-5492eafa07d3"  # Managed-AllViewer

  viewer_protocol_policy = "redirect-to-https"
  compress               = false
}
```
