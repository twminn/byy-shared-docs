# Rails App Changes for Conversion Tracking

**Priority:** Critical
**Owner:** Rails Team
**Repo:** `byy-rails`
**Related:** [Conversion Tracking Audit](./03.07.26-CONVERSION_TRACKING_AUDIT.md)

---

## Summary

The Rails app at `bestyearyet.io` already fires `purchase` events via `BYYAnalytics.trackPurchase()` on subscription success pages. However, several critical gaps exist:

1. **`sign_up` event is never fired** — This is one of two critical conversion events. The method exists in `BYYAnalytics` but is never called anywhere in the codebase.
2. `initiate_checkout` event is never fired
3. UTM parameters from landing page redirects are not captured or stored
4. No server-side event tracking for webhook-triggered purchases

### The Two Critical Conversion Events

| Event | Status | Priority |
|-------|--------|----------|
| `purchase` — subscription completed | **Working** (fires on success pages) | Maintain |
| `sign_up` — user registration + verification | **Not firing** | **Critical — implement now** |

---

## Change 1: Fire `sign_up` Event on Registration Success

### What

Call `BYYAnalytics.trackSignup()` when a new user completes registration. The method already exists in `app/javascript/analytics/gtm.js` but is never called.

### Where

The signup flow ends at the `verify_submit` action in `SignupController`, which redirects to `verified_login_path` on success. The `sign_up` event should fire after the user successfully verifies their account (not at form submission, since the account isn't confirmed until verification).

### Option A: Fire on the verification success redirect

**File: `app/controllers/signup_controller.rb`** (line ~411-419)

Add a flash flag that the verified login view can read:

```ruby
if result_ok
  Rails.logger.info("[SignupController#verify_submit] Verification approved for user_id=#{user.id}")
  
  session.delete(:verification_sid)
  session.delete(:verification_sids)
  
  # Flag for analytics tracking
  flash[:signup_complete] = true
  flash[:signup_user_id] = user.id
  
  redirect_to verified_login_path(user_secure_id: user_secure_id)
end
```

### Option B: Fire on the post-verification landing page (Preferred)

Add analytics tracking to the view that the user sees after successful verification and login. This is more reliable because `BYYAnalytics` will be loaded by the time the view renders.

**File: `app/views/signup/verified_login.html.erb`** (or the view rendered after verified login)

Add at the bottom of the view:

```erb
<% if flash[:signup_complete] %>
<script>
  document.addEventListener('DOMContentLoaded', function() {
    if (typeof BYYAnalytics !== 'undefined') {
      BYYAnalytics.trackSignup('<%= j flash[:signup_user_id].to_s %>', 'email');
      console.log('[BYY Signup] sign_up event tracked for user:', '<%= j flash[:signup_user_id].to_s %>');
    } else {
      console.warn('[BYY Signup] BYYAnalytics not available for signup tracking');
    }
  });
</script>
<% end %>
```

This follows the same pattern used for `trackPurchase()` on the checkout success page.

## Change 2: Fire `initiate_checkout` on Checkout Start

### What

Track when a user begins the Stripe checkout flow. This creates a funnel: `sign_up` → `initiate_checkout` → `purchase`.

### Where

**File: `app/controllers/stripe/checkout_controller.rb`** — `create` action (line ~64)

The `create` action creates a Stripe Checkout Session and returns `clientSecret` as JSON. Since this is an API call (not a page render), the event should be fired on the client side when the user lands on the checkout page.

### Implementation

**File: `app/views/stripe/checkout/checkout.html.erb`** (the view that mounts Stripe Embedded Checkout)

Add after the Stripe checkout mount:

```erb
<script>
  document.addEventListener('DOMContentLoaded', function() {
    if (typeof BYYAnalytics !== 'undefined') {
      // Value and plan name are available from the pricing page context
      var priceElement = document.querySelector('[data-price-value]');
      var planElement = document.querySelector('[data-plan-name]');
      var value = priceElement ? parseFloat(priceElement.dataset.priceValue) : 0;
      var planName = planElement ? planElement.dataset.planName : 'Unknown Plan';
      
      BYYAnalytics.trackInitiateCheckout(value, planName);
      console.log('[BYY Checkout] initiate_checkout tracked:', { value: value, plan: planName });
    }
  });
</script>
```

**Alternative:** If the checkout page doesn't have price data available in the DOM, pass it from the controller via instance variables:

```erb
<script>
  document.addEventListener('DOMContentLoaded', function() {
    if (typeof BYYAnalytics !== 'undefined') {
      BYYAnalytics.trackInitiateCheckout(
        <%= @checkout_value || 0 %>,
        '<%= j(@checkout_plan_name || "Unknown Plan") %>'
      );
    }
  });
</script>
```

And in the controller, set the variables before rendering:

```ruby
def checkout
  @checkout_value = params[:price_value] || 0
  @checkout_plan_name = params[:plan_name] || 'Unknown Plan'
  render 'checkout'
end
```

## Change 3: Capture and Store UTM Parameters

### What

When users arrive from landing pages with UTM parameters in the URL, capture and store them for attribution. This is critical because the landing page changes (see [03.07.26-LANDING_PAGE_CHANGES.md](./03.07.26-LANDING_PAGE_CHANGES.md)) will begin forwarding UTM params on redirect.

### Implementation

```ruby

class AddUtmTrackingToUsers < ActiveRecord::Migration[7.1]

    add_column :users, :first_touch_medium, :string
    add_column :users, :first_touch_campaign, :string
    add_column :users, :first_touch_landing_page, :string
    add_column :users, :first_touch_at, :datetime
    
    add_column :users, :last_touch_source, :string
    add_column :users, :last_touch_medium, :string
    add_column :users, :last_touch_campaign, :string
    add_column :users, :last_touch_landing_page, :string
    add_column :users, :last_touch_at, :datetime
    
    add_column :users, :gclid, :string
    add_column :users, :fbclid, :string
    
    add_index :users, :first_touch_source
    add_index :users, :first_touch_campaign
  end
end
```

#### Step 2: Capture UTMs on signup

**File: `app/controllers/signup_controller.rb`**

After creating the user (line ~95-98), store UTM params:

```ruby
success = user_service.create(params[:email], params[:password], params[:confirm_password], params[:signup_code], params[:phone])
raise StandardError, I18n.t('error.create_user_error') unless success

user = User.find_by(email: params[:email].downcase)

# Capture UTM parameters from landing page redirect
capture_utm_params(user) if user
```

Add private method:

```ruby
private

def capture_utm_params(user)
  utm_data = {
    first_touch_source: params[:utm_source],
    first_touch_medium: params[:utm_medium],
    first_touch_campaign: params[:utm_campaign],
    first_touch_landing_page: params[:source],  # Custom 'source' param from landing page
    first_touch_at: Time.current,
    last_touch_source: params[:utm_source],
    last_touch_medium: params[:utm_medium],
    last_touch_campaign: params[:utm_campaign],
    last_touch_landing_page: params[:source],
    last_touch_at: Time.current,
    gclid: params[:gclid],
    fbclid: params[:fbclid]
  }.compact
  
  user.update_columns(utm_data) if utm_data.any?
rescue StandardError => e
  Rails.logger.error("[SignupController] Failed to capture UTM params: #{e.message}")
end
```

Include first-touch and last-touch attribution data as custom parameters in the `purchase` event, so GA4 can show which campaigns drove purchases.

### Implementation

**File: `app/controllers/stripe/checkout_controller.rb`** — `prepare_analytics_data` method

Add attribution fields:

```ruby
def prepare_analytics_data(stripe_user)
  return nil unless stripe_user&.active?
  
  data = {
    transaction_id: stripe_user.stripe_subscription_id || "lifetime_#{current_user.id}_#{Time.current.to_i}",
    plan: stripe_user.plan_name || 'Unknown Plan',
    value: 0,
    currency: 'USD',
    # Attribution data
    first_touch_source: current_user.first_touch_source,
    first_touch_medium: current_user.first_touch_medium,
    first_touch_campaign: current_user.first_touch_campaign,
    first_touch_landing_page: current_user.first_touch_landing_page,
    last_touch_source: current_user.last_touch_source,
    last_touch_medium: current_user.last_touch_medium,
    last_touch_campaign: current_user.last_touch_campaign
  }
  
  # ... existing price fetching logic ...
  
  data
end
```

**File: `app/views/stripe/checkout/success.html.erb`**

Update the purchase tracking to include attribution:

## Change 5: Server-Side Purchase Tracking via Measurement Protocol (Recommended)

> **Dependency:** ~~Add GA4 API secret~~ **DONE** — Secret created and included below. No blockers.

### What

The current client-side `purchase` tracking depends on the user seeing the success page. If the page doesn't fully load, or if the user closes the browser before `DOMContentLoaded`, the purchase event is lost. Server-side tracking via the GA4 Measurement Protocol ensures every purchase is recorded.

### Implementation

The `AnalyticsService` class is already documented in the shared docs. Implement it:

**File: `app/services/analytics_service.rb`**

```ruby
class AnalyticsService
  GA4_MEASUREMENT_ID = 'G-6GPCZV3DHR'
  GA4_API_SECRET = Rails.application.credentials.dig(:google, :ga4_api_secret)
  
  def self.track_purchase(user:, transaction_id:, value:, plan:, currency: 'USD')
    client_id = user.ga4_client_id || user.id.to_s
    
    track_event(
      client_id: client_id,
      user_id: user.id.to_s,
      event_name: 'purchase',
      params: {
        transaction_id: transaction_id,
        value: value,
        currency: currency,
        items: [{ item_name: plan, price: value }],
        first_touch_source: user.first_touch_source,
        first_touch_campaign: user.first_touch_campaign,
        engagement_time_msec: 1
      }
    )
  end
  
  def self.track_event(client_id:, event_name:, params: {}, user_id: nil)
    return unless GA4_API_SECRET.present?
    
    uri = URI("https://www.google-analytics.com/mp/collect?measurement_id=#{GA4_MEASUREMENT_ID}&api_secret=#{GA4_API_SECRET}")
    
    payload = {
      client_id: client_id,
      events: [{
        name: event_name,
        params: params.compact
      }]
    }
    payload[:user_id] = user_id if user_id.present?
    
    Net::HTTP.post(uri, payload.to_json, 'Content-Type' => 'application/json')
  rescue => e
    Rails.logger.error "[AnalyticsService] Failed to track #{event_name}: #{e.message}"
  end
end
```
