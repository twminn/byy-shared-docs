## 1. Configure Cross-Domain Tracking in GA4

Cross-domain tracking preserves the user session when navigating between BYY domains. Without this, GA4 treats a redirect from `new.bestyearyet.com` to `bestyearyet.io` as two separate sessions, breaking conversion attribution.

### Steps

1. Go to [GA4 Admin](https://analytics.google.com) → Property `395609610`
2. Navigate to **Data Streams** → Select the web stream (`G-6GPCZV3DHR`)
3. Click **Configure tag settings** (at the bottom of the stream detail page)
4. Click **Configure your domains** (under Settings section)
5. Add the following domains with match type **"Contains"**:

| Match Type | Domain |
|------------|--------|
| Contains | `bestyearyet.com` |
| Contains | `bestyearyet.io` |

> Using "Contains" for `bestyearyet.com` will automatically cover `new.bestyearyet.com`, `gift.bestyearyet.com`, and any future subdomains.

6. Click **Save**

### What This Does

GA4 will automatically append a `_gl` linker parameter to outbound links between these domains. This parameter carries the GA4 client ID and session info, so the session is preserved across the redirect.

Example: When a user clicks a CTA on `new.bestyearyet.com`, the link to `bestyearyet.io` becomes:
```
https://bestyearyet.io/signup?plan=yearly&_gl=1*abc123*_ga*MTIzNDU2Nzg5MC4x...
```

### Important Notes
- This only works for `<a>` tag navigations and `window.open()`. For `window.location.href` redirects (which the landing pages use), the linker parameter must be appended programmatically. See [Landing Page Changes](./03.07.26-LANDING_PAGE_CHANGES.md) for the code change.
- After configuring, verify with GA4 DebugView that sessions persist across domains.

## 2. Verify Key Events (Conversions)

GA4 renamed "Conversions" to "Key Events" in March 2024. Events must be marked as Key Events in GA4 Admin for them to count in the `keyEvents` / `conversions` metric.

### Steps

1. Go to [GA4 Admin](https://analytics.google.com) → Property `395609610`
2. Navigate to **Events** (under Data display)
3. Verify the following events exist and are marked as Key Events:

| Event Name | Must Be Key Event | Status | Notes |
|------------|:-----------------:|--------|-------|
| `purchase` | **Yes** | Verify (15 events in last 90d) | Primary conversion — subscription purchased |
| `sign_up` | **Yes** | **Mark now** | Not currently firing — Rails changes will enable it. Mark it now so events are counted as soon as the code ships. |
| `form_submit` | No | Remove if marked | Generic form submissions should not be key events (inflates conversion counts) |

4. To mark an event as a Key Event: click the event name → toggle **"Mark as key event"**
5. **Important:** If `form_submit` is currently marked as a Key Event, **unmark it**. The audit shows 59 total key events vs only 15 purchases, meaning other events are being counted as conversions. Only `purchase` and `sign_up` should be Key Events.

### The Two Critical Conversion Events

| Event | GA4 Event Name | When Fired | Business Value |
|-------|---------------|-----------|----------------|
| **Registration** | `sign_up` | User completes account registration + verification | Contact captured — lead created |
| **Purchase** | `purchase` | Stripe subscription checkout completed | Revenue generated |

These two events are tracked **separately** throughout the marketing dashboard. They must both be marked as Key Events in GA4 for the dashboard to report them correctly.

## 3. GTM Tag Verification

Verify that GTM has GA4 Event tags configured to send custom events from the dataLayer to GA4.

### Steps

1. Go to [GTM Dashboard](https://tagmanager.google.com) → Container `GTM-K9PVK9ZF`
2. Navigate to **Tags**
3. Verify a **GA4 Event** tag exists for each of these events:

| Tag Name (suggested) | Event Name | Trigger |
|---------------------|------------|---------|
| GA4 - Purchase | `purchase` | Custom Event: `purchase` from dataLayer |
| GA4 - Sign Up | `sign_up` | Custom Event: `sign_up` from dataLayer |
| GA4 - Initiate Checkout | `initiate_checkout` | Custom Event: `initiate_checkout` from dataLayer |
| GA4 - Generate Lead | `generate_lead` | Custom Event: `generate_lead` from dataLayer |

4. Each tag should:
   - Type: **Google Analytics: GA4 Event**
   - Measurement ID: `G-6GPCZV3DHR`
   - Event Name: matching the dataLayer event name
   - Event Parameters: mapped from dataLayer variables (e.g., `transaction_id`, `value`, `currency`)

### If Tags Are Missing

Create them:

**Example — GA4 Purchase Tag:**

1. New Tag → Google Analytics: GA4 Event
2. Measurement ID: `G-6GPCZV3DHR`
3. Event Name: `purchase`
4. Event Parameters:
   - `transaction_id` → `{{DLV - transaction_id}}`
   - `value` → `{{DLV - value}}`
   - `currency` → `{{DLV - currency}}`
   - `event_id` → `{{DLV - event_id}}`
5. Trigger: Custom Event → Event name equals `purchase`

Create matching Data Layer Variables (DLV) for each parameter:
- Variable Type: Data Layer Variable
- Data Layer Variable Name: `transaction_id` (or `value`, `currency`, `event_id`)

### Test

1. Use GTM Preview mode on `bestyearyet.io`
2. Complete a test subscription (staging)
3. Verify in GTM Preview that the `purchase` event fires and the GA4 Event tag activates
4. Verify in GA4 DebugView that the event appears with correct parameters

## 4. Referral Exclusions

To prevent `bestyearyet.com` and subdomains from appearing as referral sources when users navigate between BYY properties, add referral exclusions.

### Steps

1. Go to GA4 Admin → Data Streams → Web stream
2. Configure tag settings → **List unwanted referrals**
3. Add:

| Match Type | Domain |
|------------|--------|
| Contains | `bestyearyet.com` |
| Contains | `bestyearyet.io` |

This prevents internal navigations between BYY properties from creating new referral sessions.
