# HOTFIX: /pricing Page — Empty Plan Cards and $0 Prices

**Date:** May 2, 2026
**Priority:** Urgent — pricing page is live and broken
**Owner:** Rails Team
**Status:** The experiment proxy is ACTIVE. Visitors are being assigned variants. The /pricing page currently renders no plan cards.

---

## Problem

The `/pricing` page renders with empty plan cards and `$0.00` prices. The Stimulus controller data attributes are blank:

```html
<!-- CURRENT (broken) -->
<main class="pricing-page-main"
      data-controller="pricing-page"
      data-pricing-page-annual-price-id-value=""
      data-pricing-page-monthly-price-id-value=""
      data-exp-price="pricing-v1:low">

  <!-- plan-cards-grid is EMPTY -->
  <div class="plan-cards-grid" data-pricing-page-target="cardsGrid">
  </div>
```

**Root cause:** The `data-exp-price` wrapper and variant detection are working correctly (the proxy delivers `X-BYY-Variant: pricing-v1:{variant}` and the page wraps content appropriately). However, the Stimulus controller's `annual-price-id-value` and `monthly-price-id-value` data attributes are not being populated from the variant, so `pricing_page_controller.js` has nothing to render.

---

## Fix

Map the experiment variant to the correct Stripe Price IDs and pass them to the Stimulus controller. Here is the exact mapping:

### Stripe Price ID Mapping

| Variant | Annual Price ID | Annual $ | Monthly Price ID | Monthly $ |
|---------|----------------|----------|-----------------|-----------|
| `high` | `price_1SlB5qRqUyfRcS570LxMpXq8` | $149/year | `price_1SlB6LRqUyfRcS57Sq35J41D` | $14.99/month |
| `mid` | `price_1TSPFoRqUyfRcS57i1C7lM5c` | $98/year | `price_1TSPFoRqUyfRcS57CYMnYSBg` | $9.99/month |
| `low` | `price_1TSPFqRqUyfRcS57MHx3Up2s` | $49/year | `price_1TSPFqRqUyfRcS57gdWX6UkN` | $4.99/month |

All prices are on the same Stripe product: `prod_TicKI93M1udWk7` (Best Year Yet).

### Option A: Add helper method (recommended)

If you have a `PricingHelper` or similar, add this mapping:

```ruby
# app/helpers/pricing_helper.rb (or wherever pricing logic lives)

EXPERIMENT_PRICES = {
  "high" => {
    annual_price_id:  "price_1SlB5qRqUyfRcS570LxMpXq8",
    monthly_price_id: "price_1SlB6LRqUyfRcS57Sq35J41D",
    annual_amount:    149_00,
    monthly_amount:   14_99,
    annual_display:   "$149",
    monthly_display:  "$14.99",
  },
  "mid" => {
    annual_price_id:  "price_1TSPFoRqUyfRcS57i1C7lM5c",
    monthly_price_id: "price_1TSPFoRqUyfRcS57CYMnYSBg",
    annual_amount:    98_00,
    monthly_amount:   9_99,
    annual_display:   "$98",
    monthly_display:  "$9.99",
  },
  "low" => {
    annual_price_id:  "price_1TSPFqRqUyfRcS57MHx3Up2s",
    monthly_price_id: "price_1TSPFqRqUyfRcS57gdWX6UkN",
    annual_amount:    49_00,
    monthly_amount:   4_99,
    annual_display:   "$49",
    monthly_display:  "$4.99",
  },
}.freeze

def experiment_prices
  variant = experiment_variant || "high"
  EXPERIMENT_PRICES[variant] || EXPERIMENT_PRICES["high"]
end
```

### Option B: Inline in the view (quickest fix)

If you need the fastest possible fix, hardcode in the pricing view:

```erb
<%
  variant = experiment_variant || "high"
  price_map = {
    "high" => { annual: "price_1SlB5qRqUyfRcS570LxMpXq8", monthly: "price_1SlB6LRqUyfRcS57Sq35J41D" },
    "mid"  => { annual: "price_1TSPFoRqUyfRcS57i1C7lM5c", monthly: "price_1TSPFoRqUyfRcS57CYMnYSBg" },
    "low"  => { annual: "price_1TSPFqRqUyfRcS57MHx3Up2s", monthly: "price_1TSPFqRqUyfRcS57gdWX6UkN" },
  }
  prices = price_map[variant] || price_map["high"]
%>
```

### Where to apply — the Stimulus controller data attributes

The fix goes wherever the `<main>` tag with `data-controller="pricing-page"` is rendered. The price IDs must be populated:

```erb
<main class="pricing-page-main"
      data-controller="pricing-page"
      data-pricing-page-expires-at-value="<%= @expires_at %>"
      data-pricing-page-promo-code-value="<%= @promo_code %>"
      data-pricing-page-trial-days-value="<%= @trial_days %>"
      data-pricing-page-annual-price-id-value="<%= prices[:annual] %>"
      data-pricing-page-monthly-price-id-value="<%= prices[:monthly] %>"
      data-exp-price="pricing-v1:<%= variant %>">
```

### Reading the variant

The variant comes from the `X-BYY-Variant` HTTP header set by the edge proxy. If you already have the `ExperimentAware` concern from the integration doc, `experiment_variant` returns `"high"`, `"mid"`, or `"low"`. If not:

```ruby
# Quick inline version
variant = request.headers["X-BYY-Variant"].to_s.split(":").last || "high"
```

1. Open an incognito window and visit `https://bestyearyet.io/pricing`
2. Confirm plan cards appear with pricing
3. Check DevTools → Application → Cookies for `byy_exp_variant` (e.g., `pricing-v1:mid`)
4. Verify the displayed price matches the variant:
   - `high` → $149/year, $14.99/month
   - `mid` → $98/year, $9.99/month
   - `low` → $49/year, $4.99/month
5. Click a subscribe CTA and confirm the Stripe checkout loads the correct price

To test a specific variant, set this cookie in the browser console and reload:

```javascript
document.cookie = 'byy_exp_variant=pricing-v1:mid; path=/; max-age=86400';
location.reload();
```
