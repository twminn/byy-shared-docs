## Summary

The analytics team has deployed a CloudFront edge proxy in front of `bestyearyet.io`. This proxy assigns visitors to pricing experiment variants and forwards an HTTP header to your Rails server. Your responsibility is to read this header and render the correct pricing on checkout/plan selection pages.

**Estimated effort:** 2-4 hours

---

## Change 1: Add Experiment Concern to ApplicationController

### What

Create a concern that reads the `X-BYY-Variant` header and makes the variant available to views.

### File: `app/controllers/concerns/experiment_aware.rb` (new)

```ruby
module ExperimentAware
  extend ActiveSupport::Concern

  included do
    before_action :set_experiment_variant
    helper_method :experiment_variant, :experiment_variant_for
  end

  private

  def set_experiment_variant
    raw = request.headers["X-BYY-Variant"].to_s
    @experiment_variants = {}

    raw.split(",").each do |pair|
      experiment_id, variant_id = pair.strip.split(":", 2)
      @experiment_variants[experiment_id] = variant_id if experiment_id.present? && variant_id.present?
    end
  end

  # Returns the variant for a specific experiment, or nil
  def experiment_variant_for(experiment_id)
    @experiment_variants[experiment_id]
  end

  # Returns the full variant string for the primary pricing experiment
  def experiment_variant
    experiment_variant_for("pricing-v1")
  end
end
```

### File: `app/controllers/application_controller.rb` (modify)

```ruby
class ApplicationController < ActionController::Base
  include ExperimentAware
  # ... existing code ...
end
```

## Change 2: Render Pricing Conditionally

### What

On pages that display pricing (subscription selection, checkout), use the variant to determine which prices to show.

### File: `app/helpers/pricing_helper.rb` (new or modify existing)

```ruby
module PricingHelper
  PRICING_VARIANTS = {
    "control" => {
      annual: { amount: 149_00, display: "$149/year", savings: nil },
      monthly: { amount: 14_99, display: "$14.99/month", savings: nil },
    },
    "annual-discount" => {
      annual: { amount: 99_00, display: "$99/year", savings: "Save 33%" },
      monthly: { amount: 14_99, display: "$14.99/month", savings: nil },
    },
    "monthly-focus" => {
      annual: { amount: 149_00, display: "$149/year", savings: "Best value" },
      monthly: { amount: 9_99, display: "$9.99/month", savings: "Most popular" },
    },
  }.freeze

  def pricing_for_variant(variant_id = nil)
    variant_id ||= experiment_variant || "control"
    PRICING_VARIANTS[variant_id] || PRICING_VARIANTS["control"]
  end
end
```

### File: Pricing views (e.g., `app/views/subscriptions/new.html.erb`)

```erb
<% pricing = pricing_for_variant %>

<div data-exp-price="pricing-v1:<%= experiment_variant || 'control' %>">
  <div class="plan-card annual">
    <h3>Annual Plan</h3>
    <p class="price"><%= pricing[:annual][:display] %></p>
    <% if pricing[:annual][:savings] %>
      <span class="badge"><%= pricing[:annual][:savings] %></span>
    <% end %>
  </div>

  <div class="plan-card monthly">
    <h3>Monthly Plan</h3>
    <p class="price"><%= pricing[:monthly][:display] %></p>
    <% if pricing[:monthly][:savings] %>
      <span class="badge"><%= pricing[:monthly][:savings] %></span>
    <% end %>
  </div>
</div>
```

### Critical: Only Render ONE Variant

Do **NOT** render all variants and hide with CSS/JS. The view must only output the HTML for the assigned variant's pricing. The edge proxy strips mismatched `data-exp-price` blocks as a safety net, but your server should be the primary gate.

## Change 4: Handle Missing Header Gracefully

### What

If `X-BYY-Variant` is empty or missing (e.g., during local development, or if CloudFront is bypassed), default to `"control"`.

The `ExperimentAware` concern already handles this — `experiment_variant` returns `nil` when no header is present, and `pricing_for_variant` defaults to `"control"` pricing.

For local development, you can simulate the header:

```ruby
# config/environments/development.rb (optional)
config.middleware.insert_before 0, Class.new {
  def initialize(app) = @app = app
  def call(env)
    env["HTTP_X_BYY_VARIANT"] ||= "pricing-v1:control"
    @app.call(env)
  end
}
```

## Verification Steps

1. **Header check:** Add `Rails.logger.info("Experiment variant: #{request.headers['X-BYY-Variant']}")` temporarily. Visit a pricing page — you should see a value logged.

2. **Variant rendering:** Force a visitor ID by appending `?_bvid=test-rails-001` to any URL. Check with the analytics team which variant was assigned, then verify the page shows the correct price.

3. **Source inspection:** View page source — confirm only ONE pricing variant appears in the HTML.

4. **Stripe metadata:** Complete a test checkout and verify the Stripe session metadata includes `experiment_variant`.

---

## What NOT To Do

- Do NOT implement your own assignment/randomization logic
- Do NOT store variant assignments in your own database (DynamoDB is the source of truth)
- Do NOT render multiple pricing variants with CSS display:none
- Do NOT modify the `_bvid` or `byy_vid` cookies (the edge proxy manages these)
