# Incident Report: CloudFront Proxy Broke WebSocket/ActionCable Connectivity

**Date:** May 7, 2026
**Severity:** High — Silent data loss for 5 days
**Affected:** All StimulusReflex features on `bestyearyet.io` (Rails app)
**Impact window:** May 2 - May 7, 2026
**Root cause:** Origin request policy `byy-experiment-origin-request-rails` stripped WebSocket headers
**Owner:** Rails Team (resolved), Analytics Team (prevention)

---

## Summary

When the experiment proxy was deployed on May 1-2 for `bestyearyet.io`
(distribution `E1TYH0C1AQM1MP`), the custom origin request policy
`byy-experiment-origin-request-rails` was configured with a header whitelist
containing only 4 headers:

- `X-BYY-VID`
- `X-BYY-Variant`
- `Host`
- `X-BYY-VID-New`

This caused CloudFront to strip all WebSocket handshake headers
(`Sec-WebSocket-Key`, `Sec-WebSocket-Version`, `Sec-WebSocket-Protocol`,
`Sec-WebSocket-Extensions`) before forwarding requests to the ALB. As a result,
every browser WebSocket connection to `wss://bestyearyet.io/cable` failed
silently. The Rails app uses ActionCable (WebSockets) for all real-time features
via StimulusReflex.

---

### Silent data loss (users editing with no save)

## Root Cause Detail

The experiment proxy architecture inserts a CloudFront distribution between the
browser and the ALB:

```
Browser --> CloudFront (E1TYH0C1AQM1MP) --> ALB (prod) --> ECS (Rails)
                |
                +-- Lambda@Edge: viewer-request (experiment assignment)
                +-- Lambda@Edge: origin-response (cookie injection)
                |
                +-- Origin Request Policy: byy-experiment-origin-request-rails
                    ONLY forwarded: X-BYY-VID, X-BYY-Variant, Host, X-BYY-VID-New
                    STRIPPED: Sec-WebSocket-Key, Sec-WebSocket-Version, etc.
```

CloudFront supports WebSocket connections natively, but the origin request
policy must explicitly whitelist the `Sec-WebSocket-*` headers for the handshake
to reach the origin. When headers are whitelisted, any header NOT on the list is
dropped.

The Lambda@Edge function itself handled WebSocket requests gracefully (try/except
passthrough), but the header stripping happened at the CloudFront layer before
the request reached the ALB.

---

## Fix Applied

### 1. Origin request policy updated (immediate, no deploy needed)

Added to `byy-experiment-origin-request-rails` whitelist:

```
Sec-WebSocket-Key
Sec-WebSocket-Version
Sec-WebSocket-Protocol
Sec-WebSocket-Extensions
Sec-WebSocket-Accept
```

The policy now forwards 9 headers total. This change took effect immediately
across CloudFront edge locations.

### 2. ActionCable allowed origins configured (v3.2.11)

Added to `config/environments/production.rb`:

```ruby
config.action_cable.allowed_request_origins = [
  "https://bestyearyet.io",
  %r{https://.*\.bestyearyet\.io}
]
```

### 3. Verify modal pre-rendered server-side (v3.2.10)

As a defense-in-depth measure, the verify modal (Final Monthly Score, Finalize
Plan) now renders its content directly in the ERB template rather than loading
it via StimulusReflex. This ensures the most critical user flow works even if
WebSockets are disrupted.

## Prevention: Required Changes to Experiment Infrastructure

### Update Terraform to include WebSocket headers

In `byy-marketing-analytics` → `infrastructure/terraform/cloudfront.tf`, the
origin request policy for the `bestyearyet.io` distribution MUST include
WebSocket headers. Example:

```hcl
resource "aws_cloudfront_origin_request_policy" "rails_app" {
  name = "byy-experiment-origin-request-rails"

  headers_config {
    header_behavior = "whitelist"
    headers {
      items = [
        "X-BYY-VID",
        "X-BYY-Variant",
        "Host",
        "X-BYY-VID-New",
        "Sec-WebSocket-Key",
        "Sec-WebSocket-Version",
        "Sec-WebSocket-Protocol",
        "Sec-WebSocket-Extensions",
        "Sec-WebSocket-Accept",
      ]
    }
  }

  cookies_config {
    cookie_behavior = "all"
  }

  query_strings_config {
    query_string_behavior = "all"
  }
}
```

### Add a pre-deploy checklist item

Before deploying CloudFront changes that affect `bestyearyet.io`, verify:

- [ ] Origin request policy forwards `Sec-WebSocket-*` headers
- [ ] WebSocket connections to `wss://bestyearyet.io/cable` succeed (browser console check)
- [ ] StimulusReflex features work (test any dropdown or toggle on the site)

### Consider a dedicated `/cable` cache behavior

For additional safety, create a separate CloudFront cache behavior for the
`/cable` path pattern that:

- Forwards ALL viewer headers (no whitelist filtering)
- Skips Lambda@Edge functions (no experiment assignment needed for WebSocket frames)
- Sets TTL to 0 (no caching)

This isolates WebSocket traffic from experiment logic entirely.
