# Landing Page Changes for Conversion Tracking

**Priority:** Critical
**Owner:** Frontend Team
**Repo:** `byy-landing-pages`
**Related:** [Conversion Tracking Audit](./03.07.26-CONVERSION_TRACKING_AUDIT.md)

---

## Problem

When users click CTAs on landing pages (`new.bestyearyet.com`, `gift.bestyearyet.com`), they redirect to `bestyearyet.io` via `window.location.href`. This redirect:

1. **Does not forward UTM parameters** — The original `utm_source`, `utm_medium`, `utm_campaign` etc. from the ad click URL are lost
2. **Does not include the GA4 cross-domain linker (`_gl`) parameter** — Since we use `window.location.href` (not an `<a>` tag click), GA4's automatic cross-domain link decoration does not apply

This breaks conversion attribution: GA4 sees the purchase on `bestyearyet.io` as a new `(direct)` session instead of attributing it to the original ad campaign.

## Change 2: Add UTM Forwarding and GA4 Linker Utility Functions

Add these utility functions to each landing page's `script.js` (or extract to a shared file):

```javascript
/**
 * Forward UTM parameters from the current URL to an outbound URL.
 * Also stores first-touch UTMs in a cookie for attribution.
 */
function forwardUtmParams(targetUrl) {
    const currentParams = new URLSearchParams(window.location.search);
    const utmKeys = ['utm_source', 'utm_medium', 'utm_campaign', 'utm_term', 'utm_content', 'utm_id'];
    
    utmKeys.forEach(function(key) {
        const value = currentParams.get(key);
        if (value) {
            targetUrl.searchParams.set(key, value);
        }
    });
    
    // Also forward gclid (Google Ads click ID) and fbclid (Meta click ID)
    ['gclid', 'fbclid', 'msclkid', 'ttclid'].forEach(function(key) {
        const value = currentParams.get(key);
        if (value) {
            targetUrl.searchParams.set(key, value);
        }
    });
}

/**
 * Append GA4 cross-domain linker parameter (_gl) to the URL.
 * 
 * When GA4 cross-domain tracking is configured in GTM, the gtag API
 * provides a way to get the linker parameter. This preserves the GA4
 * session across the domain redirect.
 */
function appendGaLinker(targetUrl) {
    try {
        if (typeof gtag === 'function') {
            gtag('get', BYY_CONFIG.googleAnalyticsId, 'client_id', function(clientId) {
                // The _gl parameter is automatically handled by gtag when using
                // the linker plugin. For window.location.href redirects, we need
                // to manually decorate the URL.
            });
            
            // Use the gtag linker:decorate approach
            var tempLink = document.createElement('a');
            tempLink.href = targetUrl.toString();
            
            // gtag will decorate the link with _gl parameter if cross-domain is configured
            if (typeof window.google_tag_manager !== 'undefined') {
                // GTM-based: use sendTo to decorate
                window.dataLayer = window.dataLayer || [];
                window.dataLayer.push({
                    'event': 'cross_domain_redirect',
                    'outbound_url': targetUrl.toString()
                });
            }
        }
    } catch (e) {
        console.warn('[BYY] Could not append GA linker parameter:', e);
    }
}
```

> **Note:** After GA4 cross-domain tracking is configured in GTM (see [03.07.26-GA4_GTM_CONFIGURATION.md](./03.07.26-GA4_GTM_CONFIGURATION.md)), the recommended approach is to use GTM's built-in cross-domain linker. However, since the landing pages use `window.location.href` for redirects rather than `<a>` tag clicks, the linker won't auto-decorate. The most reliable approach is to switch the redirect to use a temporary `<a>` element that GTM can decorate, or use the Measurement Protocol approach described in the alternative section below.

### Alternative: Redirect via Decorated Link (Preferred)

A more reliable approach that works with GTM's automatic cross-domain decoration:

```javascript
function redirectWithLinker(targetUrl) {
    // Forward UTM params first
    forwardUtmParams(targetUrl);
    
    // Create a temporary link element for GTM to decorate
    var link = document.createElement('a');
    link.href = targetUrl.toString();
    link.style.display = 'none';
    document.body.appendChild(link);
    
    // Small delay to allow GTM to decorate the link
    setTimeout(function() {
        window.location.href = link.href;
    }, 100);
}
```

Then use `redirectWithLinker(signupUrl)` instead of `window.location.href = signupUrl.toString()`.

## Change 3: Store First-Touch UTM Parameters in Cookie

For first-touch attribution, store the UTM parameters when a user first arrives on the landing page. This cookie will be read by the Rails app if needed.

Add this to each landing page's initialization (runs on page load):

```javascript
/**
 * Store first-touch UTM parameters in a first-party cookie.
 * Only sets the cookie if UTM params are present and no existing
 * first-touch cookie exists (preserves the original first touch).
 */
function storeFirstTouchUtm() {
    // Check if we already have a first-touch cookie
    if (document.cookie.includes('byy_ft_utm=')) {
        return;
    }
    
    var params = new URLSearchParams(window.location.search);
    var utmData = {};
    var hasUtm = false;
    
    ['utm_source', 'utm_medium', 'utm_campaign', 'utm_term', 'utm_content'].forEach(function(key) {
        var value = params.get(key);
        if (value) {
            utmData[key] = value;
            hasUtm = true;
        }
    });
    
    // Also capture click IDs
    ['gclid', 'fbclid', 'msclkid'].forEach(function(key) {
        var value = params.get(key);
        if (value) {
            utmData[key] = value;
            hasUtm = true;
        }
    });
    
    if (hasUtm) {
        utmData.landing_page = window.location.hostname;
        utmData.timestamp = new Date().toISOString();
        
        // Set cookie with 90-day expiry, SameSite=Lax for cross-domain compat
        var expires = new Date(Date.now() + 90 * 24 * 60 * 60 * 1000).toUTCString();
        // Use .bestyearyet.com domain so the cookie is accessible on bestyearyet.io? No —
        // bestyearyet.io is a different eTLD+1, so this cookie won't be readable there.
        // Instead, pass UTMs via URL params (Change 1) and let the Rails app store them.
        document.cookie = 'byy_ft_utm=' + encodeURIComponent(JSON.stringify(utmData)) + 
            ';expires=' + expires + ';path=/;SameSite=Lax';
    }
}

// Store last-touch UTMs (always overwrite)
function storeLastTouchUtm() {
    var params = new URLSearchParams(window.location.search);
    var utmData = {};
    var hasUtm = false;
    
    ['utm_source', 'utm_medium', 'utm_campaign', 'utm_term', 'utm_content'].forEach(function(key) {
        var value = params.get(key);
        if (value) {
            utmData[key] = value;
            hasUtm = true;
        }
    });
    
    if (hasUtm) {
        utmData.landing_page = window.location.hostname;
        utmData.timestamp = new Date().toISOString();
        
        var expires = new Date(Date.now() + 90 * 24 * 60 * 60 * 1000).toUTCString();
        document.cookie = 'byy_lt_utm=' + encodeURIComponent(JSON.stringify(utmData)) + 
            ';expires=' + expires + ';path=/;SameSite=Lax';
    }
}

// Call on page load
document.addEventListener('DOMContentLoaded', function() {
    storeFirstTouchUtm();
    storeLastTouchUtm();
});
```

> **Important cookie limitation:** The landing pages are on `*.bestyearyet.com` (eTLD+1: `bestyearyet.com`) while the Rails app is on `bestyearyet.io` (different eTLD+1). Cookies set on one domain **cannot** be read by the other. The UTM forwarding via URL parameters (Change 1) is the primary mechanism for passing attribution data to the Rails app. The cookie is useful for same-domain scenarios (e.g., if the user returns to the landing page).

## Change 5: Switch `gtag()` Calls to `dataLayer.push()`

Currently the landing pages call `gtag()` directly for event tracking. The shared docs recommend using `dataLayer.push()` for GTM-managed properties. While `gtag()` works when loaded via GTM, using `dataLayer.push()` ensures all events are visible in GTM's preview mode and can be acted on by any GTM tag (not just GA4).

This is a lower-priority improvement. The event tracking works as-is.

## Testing

After implementing changes:

1. **UTM forwarding test:**
   - Visit `https://new.bestyearyet.com?utm_source=test&utm_medium=cpc&utm_campaign=testing`
   - Click a CTA button
   - Verify the redirect URL to `bestyearyet.io` includes all UTM parameters
   
2. **Cross-domain linker test** (after GTM cross-domain config):
   - Visit a landing page
   - Click a CTA
   - Verify the redirect URL includes a `_gl=` parameter
   
3. **Cookie test:**
   - Visit a landing page with UTM parameters
   - Open DevTools → Application → Cookies
   - Verify `byy_ft_utm` and `byy_lt_utm` cookies are set

4. **GA4 DebugView:**
   - Use GTM Preview mode
   - Complete the full flow from landing page → signup → purchase
   - Verify in GA4 DebugView that the session is continuous (same client ID) across domains
