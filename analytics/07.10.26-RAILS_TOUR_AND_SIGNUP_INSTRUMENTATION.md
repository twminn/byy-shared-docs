## Change 1: Fire `sign_up` (re-open — Critical)

### What

Call `BYYAnalytics.trackSignup()` when a new user completes registration / email verification.

### Preferred implementation (from March 7 Option B)

1. In `SignupController#verify_submit` (or equivalent success path), set:

```ruby
flash[:signup_complete] = true
flash[:signup_user_id] = user.id
```

2. On the post-verification view (e.g. `app/views/signup/verified_login.html.erb`), fire once:

```erb
<% if flash[:signup_complete] %>
<script>
  document.addEventListener('DOMContentLoaded', function() {
    if (typeof BYYAnalytics !== 'undefined') {
      // Match the signature already defined in gtm.js — confirm param order in that file.
      // March doc used: trackSignup(userId, method)
      // If gtm.js expects (method, params), use: BYYAnalytics.trackSignup('email', { user_id: '...' })
      BYYAnalytics.trackSignup('<%= j flash[:signup_user_id].to_s %>', 'email');
    } else {
      console.warn('[BYY Signup] BYYAnalytics not available');
    }
  });
</script>
<% end %>
```

**Important:** Read `app/javascript/analytics/gtm.js` and match the live `trackSignup` signature. Do not invent a second API.

### Also cover Payment Link / post-checkout signup

Users who pay via `pay.bestyearyet.io` land on `bestyearyet.io/signup?session_id=...`. Fire `sign_up` when that account is created/verified as well (same helper / same dataLayer shape).

### Expected dataLayer

```javascript
window.dataLayer.push({
  event: 'sign_up',
  method: 'email',
  user_id: '<user_id>'
});
```

### Acceptance

- [ ] Test registration → `sign_up` in browser `dataLayer`
- [ ] Same event in GA4 Realtime (property stream for `bestyearyet.io`, `G-X84EPSV1L1`)
- [ ] Event appears for both classic signup and Payment-Link → signup paths

## Change 2: Free tour funnel events (new — Critical)

### What

Instrument the free tour (entry: `https://bestyearyet.io/` → “Start Your Tour”) so Analytics can measure:

`tour_start` → `tour_step` → `tour_complete` (or paywall) → existing `purchase`

### Events to fire

Push to `dataLayer` (and add thin wrappers on `BYYAnalytics` if that is the project convention).

| Event | When to fire | Required params |
|-------|--------------|-----------------|
| `tour_start` | User begins the free tour (first tour screen after “Start Your Tour”) | `tour_id` or session key if available; `source` query param if present (e.g. `landing_new`) |
| `tour_step` | User completes / advances each major tour step or question | `step_id` (stable string or int), `step_index` (0-based), `step_name` (human label if available) |
| `tour_complete` | User finishes the free tour content (last step before paywall / register / pricing CTA) | `steps_completed` (int) |
| `tour_paywall_view` | User sees the pay / register / pricing gate after or during tour | `plan_shown` if known |

If the product uses a single “end of tour → pricing” screen, `tour_complete` and `tour_paywall_view` may fire on the same page — that is fine; fire both once.

### Suggested helpers (add to `gtm.js`)

```javascript
// Pseudocode — match existing BYYAnalytics style
trackTourStart: function(params) {
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push(Object.assign({ event: 'tour_start' }, params || {}));
},
trackTourStep: function(params) {
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push(Object.assign({ event: 'tour_step' }, params || {}));
},
trackTourComplete: function(params) {
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push(Object.assign({ event: 'tour_complete' }, params || {}));
},
trackTourPaywallView: function(params) {
  window.dataLayer = window.dataLayer || [];
  window.dataLayer.push(Object.assign({ event: 'tour_paywall_view' }, params || {}));
}
```

### Where to wire

Exact controllers/views are owned by Rails — place calls at the real tour state transitions (Stimulus controllers, workshop steps, etc.). Requirements:

1. Fire **once per transition** (not on every re-render).
2. Preserve UTM / `source` / `_bvid` already on the URL when present; include `source` on `tour_start` when available.
3. Do not require login for tour events (tour is no-account).

### Example dataLayer payloads

```javascript
{ event: 'tour_start', source: 'landing_new' }

{ event: 'tour_step', step_id: 'q1', step_index: 0, step_name: 'Envision' }

{ event: 'tour_complete', steps_completed: 6 }

{ event: 'tour_paywall_view', plan_shown: 'annual' }
```

### Acceptance

- [ ] Start tour → `tour_start` in `dataLayer` + GA4 Realtime
- [ ] Advance 2+ steps → multiple `tour_step` events with distinct `step_index`
- [ ] Reach end / paywall → `tour_complete` and/or `tour_paywall_view`
- [ ] Events work for anonymous tour users (no account)

**Note for Analytics:** GTM/GA4 custom event tags for `tour_*` will be added by the Analytics team after Rails ships the dataLayer pushes. Rails does not need to configure GTM.
