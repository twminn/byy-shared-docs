## Summary

The analytics team has deployed a CloudFront edge proxy in front of `new.bestyearyet.com` and `gift.bestyearyet.com`. This proxy assigns visitors to pricing experiment variants and forwards a header to your Next.js server. Your responsibility is to read this header and render the correct pricing.

**Estimated effort:** 2-4 hours

## Change 1: Read X-BYY-Variant Header in Middleware

### What

Add Next.js middleware (or modify existing) to read the `X-BYY-Variant` header and make the variant available to pages.

### File: `middleware.ts` (create or modify at project root)

```typescript
import { NextRequest, NextResponse } from 'next/server';

export function middleware(request: NextRequest) {
  const variant = request.headers.get('X-BYY-Variant') || '';
  
  const response = NextResponse.next();
  
  // Pass variant to pages via a cookie readable in getServerSideProps
  if (variant) {
    response.cookies.set('x-byy-variant', variant, {
      httpOnly: true,
      secure: true,
      sameSite: 'lax',
      path: '/',
    });
  }
  
  return response;
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
};
```

### Alternative: Read directly in getServerSideProps

If you prefer not to use middleware:

```typescript
export const getServerSideProps: GetServerSideProps = async (context) => {
  const variant = context.req.headers['x-byy-variant'] as string || '';
  
  // Parse: "pricing-v1:control" → { experimentId: "pricing-v1", variantId: "control" }
  const [experimentId, variantId] = variant.split(':');
  
  return {
    props: {
      experiment: { id: experimentId || null, variant: variantId || null },
    },
  };
};
```

## Change 2: Render Pricing Conditionally

### What

Use the variant value to render the correct pricing. The variant ID tells you which price to show.

### File: Pricing component (e.g., `components/PricingSection.tsx`)

```typescript
interface PricingProps {
  variant: string | null; // e.g., "control", "annual-discount", "monthly-focus"
}

const PRICING_VARIANTS = {
  control: {
    annual: { price: 149, label: '$149/year', savings: null },
    monthly: { price: 14.99, label: '$14.99/month', savings: null },
  },
  'annual-discount': {
    annual: { price: 99, label: '$99/year', savings: 'Save 33%' },
    monthly: { price: 14.99, label: '$14.99/month', savings: null },
  },
  'monthly-focus': {
    annual: { price: 149, label: '$149/year', savings: 'Best value' },
    monthly: { price: 9.99, label: '$9.99/month', savings: 'Most popular' },
  },
};

export function PricingSection({ variant }: PricingProps) {
  const pricing = PRICING_VARIANTS[variant || 'control'] || PRICING_VARIANTS.control;
  
  return (
    <section data-exp-price={`pricing-v1:${variant || 'control'}`}>
      {/* Render pricing using the `pricing` object */}
    </section>
  );
}
```

### Critical: Only Render ONE Variant

Do **NOT** render all variants and hide with CSS/JS. The server must only output the HTML for the assigned variant. The edge proxy's content gatekeeper will strip any `data-exp-price` blocks that don't match, but relying on that is a fallback — your server should be the primary gate.

## Change 3: Add data-exp-price Safety Markers

### What

Wrap all pricing content in an element with `data-exp-price="{experiment_id}:{variant_id}"`. This allows the edge proxy's Content Gatekeeper to verify no pricing leakage.

### Example

```html
<!-- Correct: only the assigned variant's block is rendered -->
<div data-exp-price="pricing-v1:control">
  <h3>Annual Plan</h3>
  <p class="price">$149/year</p>
</div>
```

If for any reason both variants end up in the HTML (bug), the edge proxy will strip the wrong one before it reaches the browser.

## Change 4: Preserve _bvid on Checkout Links

### What

When linking to `bestyearyet.io` for checkout, ensure the `_bvid` URL parameter is preserved. The `byy-tracker.js` script handles this automatically for `<a>` tags, but if you use `window.location` navigation, use the decorator:

```typescript
// Already available from byy-tracker.js
const checkoutUrl = window.byyDecorateUrl(
  `https://bestyearyet.io/gifts?plan=${plan}&source=gift_landing`
);
window.location.href = checkoutUrl;
```

This is already documented in the cross-domain tracking spec and should be in place. Verify it still works with the new `_bvid` parameter.

## Verification Steps

1. **Header check:** Add `console.log(context.req.headers['x-byy-variant'])` in getServerSideProps temporarily. Visit the page — you should see a value like `pricing-v1:control`.

2. **Variant rendering:** Force a specific visitor ID by appending `?_bvid=test-lp-001` to the URL. Check DynamoDB (ask analytics team) for the assigned variant, then verify the page shows the correct price.

3. **Source inspection:** View page source (not DevTools Elements) — confirm only ONE pricing variant appears in the HTML.

4. **Cross-domain:** Click a checkout CTA and verify the destination URL includes `_bvid=` parameter.

---

## What NOT To Do

- Do NOT implement your own assignment logic
- Do NOT read cookies for variant assignment (the header is the source of truth)
- Do NOT render multiple pricing variants with CSS display:none
- Do NOT cache pages that contain variant-specific pricing (the edge proxy handles caching)
