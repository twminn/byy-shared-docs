## Summary

The analytics team has deployed CloudFront edge proxy distributions in front of all pricing properties. These proxies assign visitors to experiment variants and set a cookie identifying the assigned variant.

**Your sites (`bestyearyet.com`, `new.bestyearyet.com`, `gift.bestyearyet.com`) are static HTML served from S3 — there is no server-side rendering.** The correct integration approach is:

1. Embed all three variant blocks in the HTML with `data-exp-price` markers
2. Use CSS to hide all variant blocks by default (anti-flicker)
3. Use a synchronous inline `<script>` to read the `byy_exp_variant` cookie and show only the assigned variant

The `byy_exp_variant` cookie is set by the edge proxy's origin-response Lambda as a **non-HttpOnly** `Set-Cookie` header. Because browsers process response headers before parsing/executing the body, this cookie is available to `document.cookie` even on the very first page load.

**Estimated effort:** 2-4 hours

## Architecture (How It Works)

```
Visitor → CloudFront Proxy → Lambda@Edge (viewer-request)
                                  ↓
                            Assigns variant, sets headers
                                  ↓
                            Forwards to S3 origin
                                  ↓
                            S3 returns full HTML (all 3 variants)
                                  ↓
                            Lambda@Edge (origin-response)
                                  ↓
                            Sets Set-Cookie: byy_exp_variant=pricing-v1:mid
                                  ↓
                            Browser receives response
                                  ↓
                            Inline JS reads cookie, shows correct variant
```

**Key detail:** The origin-response Lambda sets cookies but does NOT modify the HTML body. Content gating (showing only the correct variant) is handled by your inline JavaScript.

## Change 1: Add Anti-Flicker CSS + Variant Script in `<head>`

Add this to every page that displays pricing. It MUST be in `<head>` before any pricing markup is parsed.

```html
<head>
  <!-- ... existing head content ... -->

  <!-- Pricing experiment: anti-flicker + variant selector -->
  <style id="exp-antiflicker">
    [data-exp-price] { display: none !important; }
    html.exp-high [data-exp-price="pricing-v1:high"] { display: block !important; }
    html.exp-mid [data-exp-price="pricing-v1:mid"] { display: block !important; }
    html.exp-low [data-exp-price="pricing-v1:low"] { display: block !important; }
  </style>
  <script>
    (function() {
      var m = document.cookie.match(/byy_exp_variant=([^;]+)/);
      if (m) {
        var parts = decodeURIComponent(m[1]).split(',');
        for (var i = 0; i < parts.length; i++) {
          var kv = parts[i].split(':');
          if (kv[0] === 'pricing-v1') {
            document.documentElement.classList.add('exp-' + kv[1]);
            return;
          }
        }
      }
      // Default to high (control) if no assignment cookie yet
      document.documentElement.classList.add('exp-high');
    })();
  </script>
</head>
```

**How this works:**
- CSS hides ALL `[data-exp-price]` elements immediately (no flash)
- Script runs synchronously before rendering, reads the `byy_exp_variant` cookie
- Adds `exp-high`, `exp-mid`, or `exp-low` class to `<html>`
- CSS shows ONLY the matching variant blocks
- If no cookie exists (edge case: experiment not active), defaults to `high`

- The attribute value MUST be exactly `pricing-v1:{variant_id}` (e.g., `pricing-v1:high`)

## Change 3: Cross-Domain Link Decorator (CRITICAL)

**Problem:** The `byy_vid` cookie is scoped to each domain. When a visitor assigned `high` on `bestyearyet.com` clicks through to `bestyearyet.io/pricing`, that domain has no knowledge of the visitor and may assign a different variant. This causes **price contamination** (visitor sees $149 on your CTA but $98 on the checkout page).

**Solution:** Add this script to the `<head>` (after the anti-flicker script). It reads the `byy_vid_xd` cookie (a non-HttpOnly copy of the visitor ID set by the edge proxy) and appends `?_bvid=` to all outbound links targeting other BYY domains.

```html
<script>
  (function() {
    var vid = (document.cookie.match(/byy_vid_xd=([^;]+)/) || [])[1];
    if (!vid) return;

    var currentHost = location.hostname;
    var byyDomains = [
      'bestyearyet.com', 'www.bestyearyet.com',
      'new.bestyearyet.com', 'gift.bestyearyet.com',
      'bestyearyet.io'
    ];

    function decorate(url) {
      try {
        var u = new URL(url, location.href);
        if (u.hostname === currentHost) return url;
        var isByy = byyDomains.some(function(d) { return u.hostname === d; });
        if (!isByy) return url;
        if (u.searchParams.has('_bvid')) return url;
        u.searchParams.set('_bvid', vid);
        return u.toString();
      } catch(e) { return url; }
    }

    // Decorate existing links on DOMContentLoaded
    document.addEventListener('DOMContentLoaded', function() {
      var links = document.querySelectorAll('a[href]');
      for (var i = 0; i < links.length; i++) {
        links[i].href = decorate(links[i].href);
      }
    });

    // Expose for dynamic navigation
    window.byyDecorateUrl = decorate;
  })();
</script>
```

**For dynamically-created links or `window.location` navigation:**

```javascript
window.location.href = window.byyDecorateUrl(
  'https://bestyearyet.io/pricing?plan=annual'
);
```

**What the Lambda does with `_bvid`:** When a visitor arrives at a new domain (e.g., `bestyearyet.io`) without a `byy_vid` cookie, the edge Lambda checks for `?_bvid=` in the URL. If found, it uses that as the visitor ID — which maps to the same DynamoDB assignment, guaranteeing the same variant across domains.

## Change 4: Remove Hardcoded Prices

Any prices currently hardcoded in JavaScript files (e.g., `config.js`, inline scripts) must be removed or wrapped in the `data-exp-price` pattern. If JavaScript dynamically inserts pricing, it should read the variant from the cookie:

```javascript
function getAssignedVariant() {
  var m = document.cookie.match(/byy_exp_variant=([^;]+)/);
  if (!m) return 'high';
  var parts = decodeURIComponent(m[1]).split(',');
  for (var i = 0; i < parts.length; i++) {
    var kv = parts[i].split(':');
    if (kv[0] === 'pricing-v1') return kv[1];
  }
  return 'high';
}
```

## Verification Steps

1. **Cookie check:** After the experiment is activated, visit any page. Open DevTools → Application → Cookies. You should see `byy_exp_variant` with a value like `pricing-v1:mid`.

2. **Variant rendering:** Check that only one pricing block is visible. Inspect the DOM — all three blocks should be present, but only one should have `display: block`.

3. **View source:** View page source — confirm all three variant blocks are present (this is expected and correct for static sites).

4. **Cross-domain:** Click a checkout CTA and verify the destination URL includes `_bvid=` parameter.

5. **Force variant:** For testing, you can manually set the cookie in DevTools console:
   ```javascript
   document.cookie = 'byy_exp_variant=pricing-v1:low; path=/; max-age=86400';
   location.reload();
   ```

## What NOT To Do

- Do NOT implement your own assignment logic — the edge proxy handles this
- Do NOT use CSS `display:none` without the anti-flicker pattern (causes flash)
- Do NOT rely on server-side rendering (your sites are static S3)
- Do NOT use the old variant names (`control`, `annual-discount`, `monthly-focus`)
- Do NOT cache-bust or bypass CloudFront — the proxy handles caching correctly

## FAQ

**Q: Will view-source expose all three prices?**
A: Yes. For static sites this is unavoidable without a server-side rendering layer. This is acceptable because: (a) users rarely view source, (b) the prices are not secret information, and (c) this matches industry standard practice for client-side A/B testing.

**Q: What if JavaScript is disabled?**
A: The page will show NO pricing (all blocks hidden by CSS). This affects <1% of users and is the standard trade-off for anti-flicker A/B testing.

**Q: What happens before the experiment is activated?**
A: No `byy_exp_variant` cookie will be set. The inline script defaults to showing `high` (control pricing). This means your current live pricing ($149/$14.99) continues to show.

**Q: What about SEO / Google crawlers?**
A: Crawlers will see all three variant blocks in the HTML. Since the prices are legitimate product pricing (not cloaking), this is compliant with Google's guidelines. The experiment uses 302 redirects nowhere, so no SEO risk.
