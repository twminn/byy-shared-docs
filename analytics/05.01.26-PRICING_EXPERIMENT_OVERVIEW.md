# Pricing Experiment Architecture — Overview

**Date:** May 1, 2026
**Priority:** High
**Owner:** Analytics Team (Marigold ONE11)
**Audience:** All BYY teams

---

## Summary

We are deploying a server-side A/B testing platform to test pricing across all BYY properties. This system uses an edge proxy (AWS CloudFront + Lambda@Edge) to assign visitors to pricing variants **before content reaches their browser**. This guarantees zero cross-contamination: a visitor who sees Price A will never see Price B or C.

## Architecture

```
User → CloudFront → Lambda@Edge (assigns variant) → Origin (renders correct pricing)
                                                   ↓
                                              DynamoDB (permanent assignment record)
```

**Key properties:**
- Assignment happens at the CDN edge, not in JavaScript
- The browser only ever receives HTML for ONE pricing variant
- Assignments are permanent (stored in DynamoDB, keyed by visitor ID)
- Works across all BYY domains via cross-domain identity propagation

## How It Works for Origin Teams

1. CloudFront sits in front of your origin server
2. Lambda@Edge assigns visitors and injects an `X-BYY-Variant` HTTP header into the request
3. Your server reads this header and renders the correct pricing
4. A secondary Lambda on the response ensures no pricing leakage in the HTML

**You do NOT need to:**
- Implement assignment logic
- Manage cookies
- Handle cross-domain identity
- Implement statistical analysis

**You DO need to:**
- Read the `X-BYY-Variant` header
- Render the correct pricing based on the variant value
- Mark pricing HTML with `data-exp-price` attributes (safety fallback)

## Header Format

```
X-BYY-Variant: {experiment_id}:{variant_id}
```

Example:
```
X-BYY-Variant: pricing-v1:high
X-BYY-Variant: pricing-v1:mid
X-BYY-Variant: pricing-v1:low
```

Multiple experiments (future):
```
X-BYY-Variant: pricing-v1:high,headline-v2:bold
```

## Experiment Naming Conventions

| Field | Format | Example |
|-------|--------|---------|
| Experiment ID | `{area}-v{N}` | `pricing-v1`, `pricing-v2` |
| Variant ID | lowercase | `high`, `mid`, `low` |
| Header value | `{exp_id}:{variant_id}` | `pricing-v1:mid` |

## HTML Safety Markers

All pricing content should be wrapped with a `data-exp-price` attribute:

```html
<div data-exp-price="pricing-v1:high">
  <span class="price">$149/year</span>
</div>
<div data-exp-price="pricing-v1:mid">
  <span class="price">$98/year</span>
</div>
<div data-exp-price="pricing-v1:low">
  <span class="price">$49/year</span>
</div>
```

The edge proxy's Content Gatekeeper strips any `data-exp-price` blocks that don't match the visitor's assigned variant. This is a safety net — your server should only render the assigned variant's content in the first place.

## Rollback Plan

If issues arise:
1. **Pause experiment:** Analytics team pauses via CLI → no new assignments, existing visitors keep their variant
2. **Emergency bypass:** CloudFront behavior can be switched to passthrough (removes Lambda@Edge) within minutes
3. **Conclude with winner:** Once a winner is determined, all visitors see the winning price permanently

## Testing / QA Procedures

1. Use `?_bvid=test-visitor-123` URL parameter to force a specific visitor ID
2. Check DynamoDB for the assignment: `pk=VIS#test-visitor-123, sk=EXP#pricing-v1`
3. Verify the `X-BYY-Variant` header arrives at your origin (log it in dev)
4. Confirm the response HTML only contains the assigned variant's pricing
5. Clear cookies and revisit — the same visitor ID (via `_bvid`) should get the same variant
