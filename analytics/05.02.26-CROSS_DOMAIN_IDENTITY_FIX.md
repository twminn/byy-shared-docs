# URGENT FIX: Cross-Domain Price Contamination

**Date:** May 2, 2026
**Priority:** Critical — causes visitors to see different prices on landing page vs checkout
**Affects:** Frontend Team (static sites)
**Status:** Analytics-side Lambda deployed. Frontend action required.

---

## Problem

A visitor on `bestyearyet.com` sees "$149/year" in the hero CTA (assigned `high`), clicks through to `bestyearyet.io/pricing`, and sees "$98/year" (assigned `mid`). Different prices across the journey = broken trust.

**Root cause:** The `byy_vid` cookie is domain-scoped. `bestyearyet.com` and `bestyearyet.io` are completely separate domains — they cannot share cookies. Each domain independently generated a new visitor ID and made its own random assignment.

---

## Fix (Two Parts)

### Part 1: Analytics (DONE)

We deployed an updated origin-response Lambda that now sets a **non-HttpOnly** cookie called `byy_vid_xd` on every response. This cookie contains the same visitor ID as `byy_vid` but is readable by JavaScript.

You can verify this cookie exists in DevTools → Application → Cookies → `byy_vid_xd`.

### Part 2: Frontend (ACTION REQUIRED)

Add the cross-domain link decorator script to `<head>` on all static sites. This script reads `byy_vid_xd` and appends `?_bvid={visitor_id}` to any outbound link targeting a different BYY domain.

**Add this after the anti-flicker script in `<head>`:**

```html
<script>
  (function() {
    var vid = (document.cookie.match(/byy_vid_xd=([^;]+)/) || [])[1];
    if (!vid) return;

    var currentHost = location.hostname;
    var byyDomains = [
      'bestyearyet.com', 'www.bestyearyet.com',
      'new.bestyearyet.com', 'gift.bestyearyet.com',
      'bestyearyet.io'
    ];

    function decorate(url) {
      try {
        var u = new URL(url, location.href);
        if (u.hostname === currentHost) return url;
        var isByy = byyDomains.some(function(d) { return u.hostname === d; });
        if (!isByy) return url;
        if (u.searchParams.has('_bvid')) return url;
        u.searchParams.set('_bvid', vid);
        return u.toString();
      } catch(e) { return url; }
    }

    document.addEventListener('DOMContentLoaded', function() {
      var links = document.querySelectorAll('a[href]');
      for (var i = 0; i < links.length; i++) {
        links[i].href = decorate(links[i].href);
      }
    });

    window.byyDecorateUrl = decorate;
  })();
</script>
```

### What this does

When a visitor on `bestyearyet.com` (visitor ID `abc123`, assigned `high`) clicks a link to `bestyearyet.io/pricing`:

- **Before fix:** Link goes to `https://bestyearyet.io/pricing` → new visitor ID → random variant
- **After fix:** Link goes to `https://bestyearyet.io/pricing?_bvid=abc123` → Lambda reuses `abc123` → same variant (`high`)

---

## How `_bvid` Works on the Receiving End

The viewer-request Lambda checks for visitor identity in this order:
1. `byy_vid` cookie (same-domain return visitor)
2. `_bvid` URL parameter (cross-domain handoff)
3. Generate new UUID (first-time visitor with no links)

When `_bvid` is present and there's no `byy_vid` cookie, the Lambda uses that ID for assignment lookup. The DynamoDB record already exists from the first domain, so the same variant is returned.
