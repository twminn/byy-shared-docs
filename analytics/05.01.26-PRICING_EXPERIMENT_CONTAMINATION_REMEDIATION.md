# Pricing Experiment — Contamination Remediation Guide

**From:** Analytics / Marketing Team
**Date:** 2026-05-01
**Priority:** HIGH — must be resolved before experiment activation

---

## Context

The pricing experiment (`pricing-v1`) tests three pricing tiers:

| Variant | Annual | Monthly | Traffic |
|---------|--------|---------|---------|
| `high` (control) | $149/yr | $14.99/mo | 50% |
| `mid` | $98/yr | $9.99/mo | 25% |
| `low` | $49/yr | $4.99/mo | 25% |

The experiment covers ALL BYY web properties: `bestyearyet.com`, `www.bestyearyet.com`,
`new.bestyearyet.com`, `gift.bestyearyet.com`, and `bestyearyet.io`.

The experiment proxy (CloudFront + Lambda@Edge) assigns visitors to variants and strips
non-matching pricing HTML from responses. However, there are surfaces that bypass this
protection. Each team has specific remediation items below.

---

## For the Frontend Team (Landing Pages)

### Issue 1: `config.js` hardcoded prices

Both `sites/new/config.js` and `sites/gift/config.js` contain:

```javascript
pricing: {
    monthlyRegularPrice: 14.99,
    annualRegularPrice: 149,
    // ...
}
```

Lambda@Edge strips HTML `data-exp-price` blocks but does NOT modify external `.js` files.
If any code reads `BYY_CONFIG.pricing` to display prices, users see control pricing
regardless of their variant assignment.

**Required fix:** Remove pricing from `config.js`. All pricing display must live inside
HTML blocks with `data-exp-price` attributes.

### Issue 2: HTML pricing markup

All pricing sections need `data-exp-price` markers. Here's the required pattern:

```html
<!-- Annual pricing -->
<div data-exp-price="pricing-v1:high">
  <p class="price">$149/year</p>
  <a href="https://pay.bestyearyet.io/b/4gMbJ3gIhcD8clB4YZaZi04">Sign Up Annually</a>
</div>
<div data-exp-price="pricing-v1:mid">
  <p class="price">$98/year</p>
  <a href="https://pay.bestyearyet.io/b/14A4gBcs15aG4T9dvvaZi06">Sign Up Annually</a>
</div>
<div data-exp-price="pricing-v1:low">
  <p class="price">$49/year</p>
  <a href="https://pay.bestyearyet.io/b/aFaeVfeA9gTo99p0IJaZi08">Sign Up Annually</a>
</div>

<!-- Monthly pricing -->
<div data-exp-price="pricing-v1:high">
  <p class="price">$14.99/month</p>
  <a href="https://pay.bestyearyet.io/b/cNibJ3dw546CclBfDDaZi05">Sign Up Monthly</a>
</div>
<div data-exp-price="pricing-v1:mid">
  <p class="price">$9.99/month</p>
  <a href="https://pay.bestyearyet.io/b/eVq8wRgIhav085lajjaZi07">Sign Up Monthly</a>
</div>
<div data-exp-price="pricing-v1:low">
  <p class="price">$4.99/month</p>
  <a href="https://pay.bestyearyet.io/b/14AfZj1Nnav085lbnnaZi09">Sign Up Monthly</a>
</div>
```

The Lambda automatically strips all blocks except the one matching the visitor's variant.
The visitor's browser only ever sees ONE pricing tier.

### Issue 3: Email templates

Remove specific dollar amounts from email templates during the experiment, or integrate
with DynamoDB to look up the subscriber's variant and template the correct pricing.

## For the Rails Team

### Issue 1: `checkout_controller.rb#pricing` — unfiltered price list

The pricing action currently does:

```ruby
prices = Stripe::Price.list(product: ENV.fetch('STRIPE_PRODUCT_KEY'), active: true, ...)
```

With three tiers on the same product, this now returns 6 prices. The view picks the first
monthly and first annual price, which may not match the visitor's assigned variant.

**Required fix:**

```ruby
def pricing
  variant = request.headers['X-BYY-Variant'] || 'high'

  # Map variant to the correct Stripe price IDs
  variant_prices = {
    'high' => { annual: 'price_1SlB5qRqUyfRcS570LxMpXq8', monthly: 'price_1SlB6LRqUyfRcS57Sq35J41D' },
    'mid'  => { annual: 'price_1TSPFoRqUyfRcS57i1C7lM5c', monthly: 'price_1TSPFoRqUyfRcS57CYMnYSBg' },
    'low'  => { annual: 'price_1TSPFqRqUyfRcS57MHx3Up2s', monthly: 'price_1TSPFqRqUyfRcS57gdWX6UkN' },
  }

  price_ids = variant_prices.fetch(variant, variant_prices['high'])
  @prices = price_ids.values.map { |id| Stripe::Price.retrieve(id, expand: ['product']) }
  @variant = variant
end
```

### Issue 2: Checkout session metadata

When creating a Stripe Checkout session, include experiment metadata for attribution:

```ruby
session_params[:metadata] = {
  experiment_variant: variant,
  byy_vid: cookies[:byy_vid]
}
```

### Issue 3: Experiment proxy activation

The experiment proxy for `bestyearyet.io` will be activated via Terraform. This will
insert a CloudFront distribution in front of the Rails app that:
- Sets the `X-BYY-Variant` header on every request
- Sets the `byy_vid` cookie for visitor identity
- Strips pricing HTML (if any) from responses

A maintenance window will be coordinated for the DNS switch. No Rails infrastructure
changes are required — only the code changes above.
